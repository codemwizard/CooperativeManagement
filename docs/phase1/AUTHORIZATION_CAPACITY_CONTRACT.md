# Phase 1 authorization dependency and revocation contract

**Contract:** `phase1-authorization-capacity-v3`
**Status:** D-04 policy remains owner-approved; the technical lock representation is reconciled by D-16 (2026-11-17). PostgreSQL race proof remains assigned to REM-WP2.4.
**Authority:** ADR-008/010/020; INV-001/018/021; `03-specification-delta.md` §§2, 10; Phase 1 REM-WP0.4.

Every allow decision records its complete decision basis. `evidence/phase1/authority-dependency-inventory.json` v2 is the authoritative Phase 1 classification of each dependency's source, runtime mutation disposition, affected scopes, and tests. The actor/tenant authority aggregate required by D-04 is retained as the `actor_tenant` row in `symphony.authority_scope_versions`; it is not a second version table and is not the only scope row. The Phase 1 lockable scopes are `global_policy`, `organization`, `tenant`, `actor_tenant`, and `actor`. Person/shared-identity and ineligibility are explicitly excluded from Phase 1 serialization and remain original Phase 2 carry-forward.

Protected command authorization and every supported authority mutation run in the same PostgreSQL transaction as their protected/source writes. First acquire the existing command-target aggregate lock when the command has one. Then derive the complete authority scope set from trusted persisted context, ensure its version rows exist, and lock every row in canonical order: `global_policy`, `organization`, `tenant`, `actor_tenant`, `actor`; within each rank sort by `COALESCE(tenant_id::text, '') COLLATE "C"`, then `scope_id::text COLLATE "C"`. Database identity is `(scope_type, tenant_id, scope_id)` with `UNIQUE NULLS NOT DISTINCT`; exact tuple encodings and constraints are in the D-16 specification. Do not include `person/shared-identity` in a Phase 1 lock set. Protected commands use `SELECT ... FOR SHARE` on each scope row; authority-changing transactions use `SELECT ... FOR UPDATE` on each same row. Hold locks to transaction end and read dependency source rows only after all required scope locks are held. `FOR SHARE` permits concurrent protected commands while conflicting with the mutator's `FOR UPDATE`, preserving the approved D-04 serial outcomes. The first completed lock set linearizes the operation: a command that locks before revocation may commit first; a command that locks after committed revocation must observe the new fact and deny. Never decide from a pre-lock snapshot, release locks before commit, or increment authority versions for a read-only command. Bounded `40001`/`40P01` retries reuse the same command ID and semantic envelope.

The table DDL, key tuple encoding, RLS/privileges, writer/freeze matrix, lock-order algorithm, and PostgreSQL concurrency cases are frozen in [`evidence/phase1/wp2.4/authority-scope-serialization-spec.md`](../../evidence/phase1/wp2.4/authority-scope-serialization-spec.md). Capacity and delegation grant/revoke are the only supported Phase 1 authority mutations and are owned by REM-WP2.3; their source DML and version increments must share one transaction and take `FOR UPDATE` on every affected row. Tenant membership, platform-role assignment/catalogue, appointments/source status, organization/cohort reassignment, and policy/configuration writes are frozen during Phase 1 serving runtime; `symphony_app` must have no DML privilege on those source tables, and registry/startup validation must reject mutation paths for them. The inventory contains corresponding negative PostgreSQL privilege and command-registration proofs rather than race tests for nonexistent writers. Phase 2 person/shared-identity handling has its own future serialization specification under IMP-P2-WP2.7 and is not a REM-WP2.4 Phase 1 prerequisite. The version trigger permits only `OLD.version + 1` updates and sets `updated_at`; runtime input never supplies either value. Multi-scope mutations lock all affected organization/tenant/actor_tenant rows in canonical order before writing and increment each changed scope once. History rows remain immutable; revocation changes future authority only.
