### 3.1 Request and response contract to test verbatim

The v1 JSON request is `{ commandId: UUID, organizationId: UUID, occurredAt: RFC3339, deviceId?: UTF-8 string of 1–128 bytes, expectedVersion: nonnegative safe integer | null, type: registered command discriminator, schemaVersion: registered version, payload: command-specific strict object }`. Enforce the 1 MiB limit while collecting raw request bytes, before parsing. The command route must receive a `Buffer` from a Fastify `application/json` content parser registered in the route's encapsulated plugin before the default parser can consume the payload (`parseAs: 'buffer'`, explicit `bodyLimit: 1_048_576`). Do not call `JSON.parse` before strict validation. Decode with fatal UTF-8 behavior; reject malformed byte sequences rather than replacing them. The strict JSON tokenizer/parser must reject duplicate object keys after escape decoding, so ``"a"` and `"\u0061"` collide, and reject invalid Unicode including lone escaped high/low surrogates. Only absent/identity `Content-Encoding` is accepted; reject compressed request bodies as HTTP 415 `UNSUPPORTED_MEDIA_TYPE`, so the byte cap has one unambiguous meaning and no decompression path. Reject unknown request/payload fields, unknown type/schema and invalid command payload before acceptance. Apply registered defaults before semantic digest. `organizationId` is a business target, not a tenant identifier; resolve it through trusted tenant-scoped database data inside the command transaction. Never compare UUID equality as proof of ownership. A nonexistent organization and one owned by a different tenant must produce the same non-disclosing failure, with no business receipt, mutation, event or outbox effect; apply the existing security-attempt audit requirement when the failure is classified as an authenticated authorization denial. The request must not set tenant, actor, role, capacity, appointment, delegation, approval, server time or authority. Each supported command targets exactly one UUID aggregate; multi-aggregate commands fail closed.

`occurredAt` is a client-asserted event time and untrusted attribution only. The server-generated `recorded_at`/transaction-start timestamp is authoritative for recording/audit chronology; aggregate version defines event ordering. Never use `occurredAt` for acceptance time, authorization, expiry, retention or ordering, and exclude it from the semantic digest as required by `COMMAND_TRANSACTION_CONTRACT.md`. A replay with a different `occurredAt` is therefore still the same semantic command: return the originally stored safe result and preserve the original accepted attribution; do not overwrite it during replay. D-15 resolves the prior range ambiguity: accept syntactically valid RFC3339 instants representable by both the application parser and PostgreSQL `timestamptz`, with no past/future skew window; reject malformed or unrepresentable values as 400 `INVALID_COMMAND`. Tests must cover ordinary historical/future values, parser/storage range boundaries, malformed offsets and replay preservation. D-15 also fixes unsupported content encoding to 415, unexpected non-retryable errors to generic 500, and missing/cross-tenant organization targets to the same audited 403. These API semantics are defined in `docs/phase1/API_CONTRACT.md` and `COMMAND_TRANSACTION_CONTRACT.md`; no owner decision is outstanding for them.

Success is HTTP 200 with `{ commandId, result: CommandResultV1, replayed }`. First success has `replayed:false`; same-actor/same-envelope retry returns the original `commandId` and result with `replayed:true`, without repeated events/outbox effects. Accepted deterministic stale-version conflict is HTTP 409 with a safe `VERSION_CONFLICT` result and `replayed:false`; replay returns the same safe result with replay metadata true. Key reuse with different actor/envelope is HTTP 409 `IDEMPOTENCY_KEY_REUSED` without stored-result fields. Other required mappings are:

| Condition | Status | Public body code |
|---|---:|---|
| Unsupported content type | 415 | `UNSUPPORTED_MEDIA_TYPE` |
| Unsupported non-identity `Content-Encoding` | 415 | `UNSUPPORTED_MEDIA_TYPE` |
| Body exceeds 1 MiB | 413 | `REQUEST_TOO_LARGE` |
| Malformed bytes/JSON, duplicate keys, invalid Unicode | 400 | `INVALID_JSON` |
| Valid JSON but invalid command schema | 400 | `INVALID_COMMAND` with safe path/code issues only |
| No valid persisted session | 401 | `UNAUTHENTICATED` |
| Invalid/missing CSRF token or Origin | 403 | `CSRF_REJECTED` |
| Forced-password-change session | 403 | `FORCED_PASSWORD_CHANGE_REQUIRED` |
| Authenticated authorization denial after durable audit, including target organization that is missing or belongs to another tenant | 403 | `NOT_AUTHORIZED` (same body for both organization cases) |
| Audit write/mode unavailable or retryable infrastructure failure | 503 | `COMMAND_TEMPORARILY_UNAVAILABLE`, `retryable:true` |
| Unexpected, non-retryable internal application error | 500 | `INTERNAL_ERROR` |

Responses must match strict shared response schemas; no SQL, exception text, policy explanation, payload, credential, token, stored result, or internal denial classification may escape. An unexpected non-retryable error returns generic HTTP 500 `INTERNAL_ERROR`, without `retryable:true` or exception details. HTTP 503 is reserved for a classified temporary outage, required audit-storage failure, or transaction outcome that must be resolved by retrying the same command ID. An uncertain commit must remain outcome-neutral; the client retries the same ID and the server resolves via the existing receipt contract.
